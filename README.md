# Solar Filament Segmentation — Kaggle 2026

太阳 Hα 图像中的暗条（filament）实例分割。指标为 **Panoptic Quality**：

```
PQ = Σ IoU(TP) / (|TP| + 0.5·|FP| + 0.5·|FN|)
```

TP 要求 IoU > 0.5，一对一贪心匹配。

**最终线上得分：0.32**（public leaderboard，14 次提交中的最高档，4 次独立复现）
**榜单参照**：第 1 名 0.70，第 10 名 0.60，参赛队约 1500

## 1. 问题与数据

### 数据

| 项目 | 数值 |
|---|---|
| 训练图像 | 707 张，2048×2048 灰度 JPEG |
| 测试图像 | 180 张，同规格 |
| COCO 图像记录 | 1154 条 —— 但只有 707 个唯一 `file_name` |
| 标注总数 | 8199 条，去重后 **5597** 条 |
| 实例面积 | 最小 9 px² / 中位 1215 px² / 最大 35251 px² |
| 小目标占比 | 15.4% 的实例 < 500 px² |

**重复标注问题**：296 个文件有 2–3 套标注记录。实测跨记录配对的 IoU>0.5 占 57.7%，
说明它们是同一批暗条的重复标注而非新目标。策略是**每个文件保留标注最丰富的一套**
（5597 条 = union 的 68.3%）。

被丢弃的 2602 条标注经核查：与已用标注的逐文件重合度**中位 0.79**，且面积更大
（中位 1428 vs 1135 px²）。不是遗漏的新目标，只是标得更宽松。

### 提交格式

CSV，无表头引号，**必须 LF 换行**：

```
filament_id,segmentation_rle
20110109104734Ch_1,<COCO compressed RLE>
```

- `filament_id` = `<图像文件名去扩展名>_<序号>`
- RLE 只能是 COCO 压缩计数（纯 ASCII 数字与空格）
- 画布固定 2048×2048

### 暗条的成像特征

暗条在 Hα 中是**暗的、细长的、弯曲的**结构。三个直接后果：

1. 需要局部对比度增强，而非全局拉伸
2. 细长结构对边界精度敏感 → PQ 的 IoU>0.5 门槛很关键
3. 实例之间可能贴得很近，需要区分

## 2. 最终方案

### 预处理：blackhat 顶帽变换

这是全项目**收益最大的单项决策**。

用椭圆核（k=41）做形态学 blackhat，提取比周围暗的局部结构，再用
`median ± 6·MAD` 归一化。

各方案的阈值可分性（AUC，衡量前景/背景分布的可分程度）：

| 预处理 | AUC |
|---|---|
| **blackhat k=41** | **0.848** |
| 局部 z-score | 0.785 |
| 原始像素 | 0.614 |
| CLAHE | 0.500（完全无效） |

两个细节：

- **不能用分位数归一化**：0.5% 分位数会截断约 20% 的暗条像素。用 median±MAD。
- **核大小选 41**：实测暗条的局部环形对比度为 −13.9 灰度级，41 px 的核能覆盖
  暗条宽度的一个完整周期。

整图 blackhat 耗时 527 ms，太慢无法在线做，因此**预计算缓存**（887 张，3.5 GB）。

### 模型：ResUNet

约 13.5M 参数，编码器 base 32、5 级残差块，双头输出（前景概率 + 边界概率）。

| 超参 | 值 |
|---|---|
| 输入 | 单通道 768×768 crop |
| 优化器 | AdamW, weight_decay 1e-4 |
| 学习率 | OneCycle，峰值 8e-4 |
| batch | 4 |
| 每 epoch 步数 | 120 |
| epoch | 300 |
| 损失 | BCE + soft Dice，`fn_weight=2.0` |
| 精度 | bf16 autocast |
| 采样 | 80% 窗口以标注为中心 |
| 增强 | 翻转、旋转、缩放、亮度、高斯噪声 |

偏置初始化：前景 −4.0、边界 −2.0（应对前景占比极低）。

### 推理：多尺度 × 翻转 TTA

对每张图跑 **2 尺度 × 3 方向 = 6 次前向**，概率平均后解码一次：

- 尺度：768、1024（stride 均为 0.75×）
- 方向：原图、左右翻、上下翻

实测阶梯（60 张图，固定解码参数）：

| 配置 | PQ | 前向次数 |
|---|---|---|
| 768 单尺度 | 0.4320 | 1 |
| 768 × lr+ud | 0.4357 | 3 |
| 768+1024 × id | 0.4318 | 2 |
| **768+1024 × lr+ud** | **0.4378** | **6** |
| 768+1024 × all4 | 0.4364 | 8 |

6 次是最优点。加 transpose 变成 8 次反而下降。

### 解码：连通域 + 边界门控

```
fg_thr=0.30, min_area=500, bd_support=0.45, rim_k=5
```

1. 前景概率 > `fg_thr` 二值化
2. 8-连通域提取候选
3. 面积 < `min_area` 丢弃
4. 对每个候选，取其外缘 5×5 环，要求环内**边界概率均值 ≥ `bd_support`**

第 4 步是单个最有效的过滤。判别力对比：

| 判据 | AUC |
|---|---|
| **边界环响应** | **0.782** |
| 前景置信度 | 0.702 |

`bd_support` 从 0.35 提到 0.45 使线上从 0.30 升到 0.32，是整个项目中线上分数
的第二次跃升。

### 兜底

若某张图解码出 0 个实例，逐级放宽阈值重试：

```
(0.20, 300, 0.30) → (0.12, 150, 0.15) → (0.08, 80, 0.0)
```

**只对空图生效**，不可能影响已有预测的图像，因此对指标的影响非负。
实测在测试集的 2 张图上触发，救回 9 个实例。

## 3. 关键发现

### 3.1 线上排行榜评的是困难子集

这是最关键的认知。六个提交的本地 pooled PQ 从 0.2534 升到 0.4393（+76%），
线上却始终在 0.28–0.29。

逐一排除后的结论：

| 假设 | 验证方式 | 结论 |
|---|---|---|
| 提交管线有 bug | CSV 往返解码 PQ=0.4074，RLE IoU=1.000000 | 排除 |
| 训练/测试分布不同 | 均值比 0.998，标准差比 1.013 | 排除 |
| 指标公式理解错 | 试了 5 种变体（逐实例 Dice 0.6077、语义 Dice 0.6379、逐图 PQ 0.4063、匹配 IoU 0.4955、召回 0.6519） | 都不接近 0.29 |
| 随机波动 | 随机半集分布 [0.375, 0.429] | 0.29 偏离 10.5 个标准差 |

唯一匹配 0.29 的量是**最难 30% 图像的 PQ = 0.2876**。

进一步做分位分析，确认线上分数精确对应**本地最差 25% 图像（Q1）**：

| 分位 | 单尺度 | 多尺度 | 变化 |
|---|---|---|---|
| **Q1 最难** | 0.2906 | 0.3018 | **+0.0112** |
| Q2 | 0.4145 | 0.4204 | +0.0058 |
| Q3 | 0.4913 | 0.4880 | −0.0033 |
| Q4 最易 | 0.5757 | 0.5796 | +0.0039 |

线上 0.30 正好对上 Q1 的 0.30，而 pooled 0.44 完全对不上。

**据此把解码参数从"全局最优"改为"Q1 最优"，线上从 0.30 升到 0.32。**
这是本项目的核心方法论收获。

> **但这个指标也有边界**：它在**只调解码器**时精确跟踪线上；换成换模型时，
> 我曾误以为它失效（union 模型 Q1 更高但线上更低）。事后复核发现两次用的
> 缓存和参数口径不同，不可比。用统一口径重测 5 种指标，全部正确排序
> （见 §3.4）。所以 Q1 是有效的，前提是**口径必须一致**。

### 3.2 集成是负收益

所有集成组合都被最强单模型打败。100 张图、多尺度推理下：

| 方案 | PQ |
|---|---|
| **u300 单模型** | **0.4393** |
| ultra + w36_200 | 0.4354 |
| ultra 单模型 | 0.4319 |
| w36_200 单模型 | 0.4289 |
| ALL-11 集成 | 更低 |

机制：弱模型拉低 TP（把本来能匹配上的实例的 IoU 稀释了）。三个独立的
比较脚本（`combos.json`、`cmp_top3.json`、`cmp_union.json`）结论完全一致。

### 3.3 训练时长的平台在 300 epoch

| run | epoch | PQ（多尺度，40 图） |
|---|---|---|
| **u300** | 300 | **0.4617** |
| u450c | 450 | 0.4595 |
| w36_200 | 200 | 0.4395 |
| ultra | 200 | 0.4305 |

450 epoch 多烧 4.8 小时换 −0.0022。300 epoch 已饱和。

### 3.4 五个指标都能正确排序，pooled 最简洁

在 60 张图上对比 u300 与 union300（已知线上 0.32 > 0.30）：

| 指标 | u300 | union300 | 符合线上 |
|---|---|---|---|
| **A pooled PQ** | 0.4320 | 0.4308 | ✓ |
| B Q1 PQ | 0.2975 | 0.2906 | ✓ |
| C 低阈值 pooled | 0.4231 | 0.4067 | ✓ |
| D 平均逐图 PQ | 0.4351 | 0.4343 | ✓ |
| E 密集场景 pooled | 0.4349 | 0.4280 | ✓ |

结论：**用 pooled PQ（A）做模型选择**，用 Q1 做解码器调优。

### 3.5 24 张图的验证集不可信

这个教训反复出现：

| 案例 | 24 图结论 | 100 图结论 |
|---|---|---|
| 1024 原生分辨率 | 0.2841 > u300 0.2799 | **0.4201 < 0.4617** |
| lr6 学习率 | 0.2926 > u300 0.2799 | 0.4325 ≈ 0.4320 |

24 图上"提升 2 个点"完全可能是噪声。**所有模型比较必须用 ≥50 张图。**

### 3.6 采样覆盖率不是瓶颈（一个被推翻的假设）

初始测量显示"400 次随机窗口只触及 18.9% 的真值实例"，看起来像重大发现——
81% 的暗条从未被训练看到。于是实现了网格覆盖采样（100% 覆盖）。

结果**更差**：fn 从 96 暴增到 165。

复查发现原始测量是**小样本误判**。用真实训练预算（120 步 × 300 轮 = 36000 次
抽样）重测：

| 采样策略 | 正样本率 | 覆盖率 | 独特性 |
|---|---|---|---|
| **随机 20000 次** | **96.3%** | **99.9%** | **99.6% 不重复** |
| 固定网格 | 73.8% | 100% | 0%（每轮完全相同） |

随机采样本来就有 99.9% 覆盖率。网格失败的真因是**零多样性**导致过拟合到
固定窗口。这个方向从一开始就是伪问题。

## 4. 上限分析：为什么停在 0.32

### 4.1 "理想分组能到 0.67" 是虚高的

给每个 GT 实例分配与其重叠的前景像素，得到一个"用 GT 裁剪"的预测，测得
Q1 = 0.6718。但这**用 GT 删掉了所有误检像素**，真实解码器做不到。

分解后看清了原因：

| 阈值 | GT 像素高于阈值（召回上限） | mask 中落在 GT 外（误检） | 逐实例 IoU 中位 |
|---|---|---|---|
| 0.30 | 83% | **32.7%** | 0.830 |
| 0.10 | 85% | 35.7% | 0.854 |
| 0.05 | 87% | 37.2% | 0.868 |

召回很高，**精度只有约 63%**。

### 4.2 真实可达上限约 0.43

| 解码器 | PQ |
|---|---|
| 连通域（可实际部署） | **0.4273** |
| 分水岭（即使已知真实实例数） | 0.2637 |

分水岭给正确的实例数也只有 0.26，**连通域已是最优的实例分组**。

### 4.3 分组不是瓶颈

| 失败类型 | 数量 | 占比 |
|---|---|---|
| 一个组件覆盖 2+ GT（合并失败） | 6–10 | **1.0–1.6%** |
| GT 被切成 2+ 块（切分失败） | 40 | 7.7% |
| GT 完全漏检 | 58–75 | 11–15% |

合并失败只有 1%，说明连通域几乎完美地对应 GT 实例。改进分组算法没有空间。

### 4.4 瓶颈是概率精度

33–37% 的前景像素落在 GT 外，而且**分散在边界**而非集中成块——硬负样本挖掘
在 707 张图里只找到 23 个高误检 patch（跨 10 张图）。这说明简单的难例重采样
无法清理，需要模型本身更精确。

**诚实结论**：本地 0.4320 已落在可达区间 0.4273–0.4378 内，当前配置基本吃满
了"blackhat + ResUNet + 连通域 + 边界门控"这套方法。

0.32 → 0.60 的差距需要架构级改变：

1. **端到端实例分割网络**（Mask R-CNN / QueryInst / SOLOv2），而非
   "语义分割 + 连通域"——后者的实例分组能力上限已到这里
2. **更多训练数据**：707 张对实例分割偏少
3. **预训练编码器**：这是我在最后 30 小时才启动的方向（`train_smp.py`），
   因时间不足未能完成验证

## 5. 失败方向的完整清单

全部有实测数据。这类"负结果"对后来者最有价值——它们看起来都很有道理。

### 模型架构

| 尝试 | 结果 |
|---|---|
| 1024 原生分辨率 | 100 图 0.4201 < 768 的 0.4617 |
| 896 crop | 0.2538（24 图），劣 |
| base 36 / 40 / 48 | 全部劣于 base 32；base 40/48 还触发 TBE 编译崩溃 |
| UNet 替代 ResUNet | 劣 |
| 预训练编码器（ResNet18/34, EfficientNet-B0） | **最后 30h 启动，未完成** |

### 训练策略

| 尝试 | 结果 |
|---|---|
| 450 / 500 epoch | 无提升（0.4595 < 0.4617）；500ep 从未跑起来（TBE 崩溃） |
| 伪标签（3 次迭代） | 0.2609 / 0.2740 / 0.2770 / 0.2712 —— 全部低于纯监督 |
| 弹性形变增强 | elas300 0.2769 ≈ u300 0.2799，无收益 |
| 难例加权采样 | **代理指标失效**：标注统计量与难度的相关仅 \|rho\| ≤ 0.161 |
| pos_prob 0.5 / 0.65 | 0.2676 / 0.2679 < 默认 0.8 的 0.2799 |
| union 标注（8199 条） | 线上 0.30 < 0.32 |
| 网格覆盖采样 | fn 从 96 暴增到 165 |

### 推理

| 尝试 | 结果 |
|---|---|
| 集成（5 种组合） | 全部劣于单模型 |
| 三尺度（+1280） | 逐图胜率仅 46/100，bootstrap 跨零 |
| 4 翻转（+transpose） | 0.4364 < 3 翻转的 0.4378 |

### 后处理

| 尝试 | 结果 |
|---|---|
| 膨胀 mask | **灾难**：0.4393 → 0.3178（r=2）→ 0.0345（r=8） |
| 合并近邻碎片 | 无变化（碎片本来不接触）；gap=6 仅 0.4393→0.4414 |
| 自适应阈值（按密度） | 0.4380，不加分 |
| 全局降到 thr=0.07 | 困难集 +0.014 但整体 −0.003 |
| 分水岭实例分离 | 0.0971（且已知真实实例数也只有 0.2637） |
| CLAHE | AUC 0.500，完全无效 |
| `rim_k=9` | boundary 门控被稀释失效，PQ 归零 |
| 面积 80–900 / 阈值 0.05–0.45 / bd 0.35–0.65 | 全网格扫描过，最优点就是当前配置 |

### 其他

| 尝试 | 结果 |
|---|---|
| Test-time adaptation | 训练/测试分布偏移全部 < 0.35 sd，无空间 |
| 硬负样本挖掘 | 707 图只找到 23 个 patch，不足以训练 |

## 7. 工程陷阱

这些坑都在 Ascend NPU 上踩过，值得记录。

### 覆盖 `PYTHONPATH` 会让 NPU 算子编译失败

```bash
export PYTHONPATH=$ROOT/src          # ✗ RuntimeError: AclSetCompileopt 500001
export PYTHONPATH=$ROOT/src:$PYTHONPATH   # ✓
```

A/B 验证过三次：不设 PYTHONPATH 正常，覆盖失败，追加正常。原因是 torch_npu
依赖 PYTHONPATH 中已有的路径来定位算子编译组件。

### CSV 必须 LF 换行

CRLF 会给每行 RLE 尾部加 `\r`。Python 的 COCO 解码器容忍它（往返 IoU 仍是
1.000000），但严格的评分器可能拒绝它。写法：

```python
csv.writer(f, lineterminator="\n")   # 配合 open(..., newline="\n")
```

### 其他

| 陷阱 | 现象 | 处理 |
|---|---|---|
| `rim_k=9` | boundary 门控被稀释，PQ 归零 | 只用 rim_k=5 |
| `/tmp` 满 | 报假的 `No module named 'tbe'` | `TMPDIR` 指向数据盘 |
| numpy 2.x | `_ARRAY_API not found` | 钉回 1.26.4 |
| `base=40` / 896 crop | TBE Subprocess 崩溃 | 用 base 32/24 + 768 |
| NFS 多进程退出 | `OSError: Directory not empty` | 无害，过滤日志即可 |
| PowerShell 写文件 | BOM 导致 Python 无法解析 | 用 `UTF8Encoding($false)` |
| SSH 内联引号 | 分号/括号/`$` 被本地 shell 解释 | 写 `.sh` → scp → 远端执行 |

## 8. 反思

### 做对的

1. **每次改动都量化**：20+ 个方向每个都有对照实验和具体数字，没有凭感觉决策。
2. **识别出线上指标的真实含义**：从"本地升 76% 线上不动"的困惑，到用分位
   分析定位到 Q1，再据此调参拿到 +0.02。这是唯一真正的突破。
3. **计算真实上限**：发现 oracle 0.67 是虚高的，诚实上限 0.43。这避免了在
   已饱和的方向上继续烧时间。
4. **接受负结果**：集成、伪标签、覆盖率、难例加权都在有数据后立刻放弃，
   没有因为"已经投入"而继续。

### 做错的

1. **过度依赖 24 张图的验证**。这个错误犯了不止一次（1024 分辨率、lr6），
   每次都得出错误结论。应该在项目早期就固定用 100 张。
2. **在伪标签上花了三轮**。第一次结果就已经明显低于监督基线（0.2609 vs
   0.2799），不该再试第二次第三次。
3. **采样覆盖率假设没有先做大样本验证**。基于 400 次抽样就下了结论，
   实际 36000 次抽样的覆盖率是 99.9%。一个本可 10 分钟排除的伪问题，
   花了数小时实现网格采样并训练了两个模型。
4. **预训练编码器启动太晚**。服务器上早就有 `segmentation_models_pytorch`
   和 `timm`，这是最可能突破的方向（ImageNet 的低层方向性边缘滤波器对
   细长暗条应该有效），但直到最后 30 小时才开始。应该在做完上限分析、
   确认瓶颈是精度之后**立刻**转过去。

### 如果重来

按优先级：

1. **第一周就上预训练编码器**（ResNet34/50 + UNet 或直接实例分割头），
   而不是从零训练小 ResUNet
2. **第一周就上端到端实例分割**（Mask R-CNN / SOLOv2），而不是
   "语义分割 + 连通域"——后者在 §4 已被证明分组能力到顶
3. 固定 100 张验证集，禁止用 24 张做决策
4. 任何"发现"先用大样本验证再实现
